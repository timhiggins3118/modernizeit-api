# ModernizeIT Architecture Ideas - January 2, 2026

## Overview

High-level architecture discussion for deploying ModernizeIT to AWS with a downloadable desktop version.

## Deployment Targets

### 1. AWS Cloud (100% AWS)

**API Layer (FastAPI)**
- Runtime: EC2 (preferred)
- Purpose: All business logic, transformation orchestration

**Portal (React UI)**
- Runtime: **S3 + CloudFront** (recommended for static SPA)
- Purpose: Web-based user interface
- Why it works: React app is static files (HTML, JS, CSS) - all "dynamic" behavior is either JavaScript in browser or API calls to FastAPI

**Database(s)**
- **Aurora PostgreSQL Serverless v2** - Relational data
  - Accounts
  - Applications
  - Jobs
  - Settings
- **S3** - Artifacts/Objects
  - JSON reports
  - Generated code ZIPs
  - COBOL uploads
  - Logs

### 2. Desktop Version (Electron)

**Same as Portal but local**
- Runtime: Electron (Windows/Mac)
- Database: SQLite (local)
- Sync: Can sync back to AWS via API

## Portal Decision: Why S3 + CloudFront?

### What is CloudFront?

CloudFront is AWS's CDN (Content Delivery Network). It caches and serves static files from 200+ edge locations worldwide.

### How It Works for React Apps

```
┌─────────────────────────────────────────────────────────┐
│  What S3+CloudFront serves (STATIC FILES):              │
│  - index.html (same file for everyone)                  │
│  - bundle.js (compiled React code)                      │
│  - styles.css                                           │
│  - images/fonts                                         │
└─────────────────────────────────────────────────────────┘
                         │
                         ▼
┌─────────────────────────────────────────────────────────┐
│  What happens IN THE BROWSER (DYNAMIC BEHAVIOR):        │
│  - React renders UI                                     │
│  - User logs in → API call to FastAPI                   │
│  - Load projects → API call to FastAPI                  │
│  - Run workflow → API call to FastAPI                   │
│  - Drag/drop nodes → JavaScript in browser              │
│  - File upload → API call to FastAPI                    │
└─────────────────────────────────────────────────────────┘
```

### S3 + CloudFront vs EC2 for Portal

| Feature | EC2 (nginx) | S3 + CloudFront |
|---------|-------------|-----------------|
| Cost | ~$15-50/mo always on | ~$1-5/mo (pay per request) |
| Speed | Single location | 200+ edge locations globally |
| HTTPS | You configure | Built-in, free cert |
| Maintenance | You manage server | Zero |
| Scaling | You handle it | Automatic |

### Why Our App Qualifies

"Static" doesn't mean "no interactivity." It means the server doesn't generate HTML per request.

Our app is a **Single Page Application (SPA)**:
- Build step creates static files (`npm run build`)
- All interactivity is JavaScript in browser
- All data comes from API calls to FastAPI
- No server-side rendering needed

**Decision: S3 + CloudFront for Portal** - cheaper, faster, zero maintenance.

## Database Decision: Why Aurora PostgreSQL?

### Considered Options

| Option | Pros | Cons |
|--------|------|------|
| **DynamoDB** | Serverless, fast | NoSQL mindset, no joins, complex for relational data |
| **MongoDB** | Flexible schema | Overkill for settings/config, not AWS-native |
| **RDS PostgreSQL** | Standard Postgres | Always-on cost, manual scaling |
| **Aurora PostgreSQL Serverless v2** | Scales to zero, Postgres-compatible, relational | Slightly higher cost when active |

### Decision: Aurora PostgreSQL Serverless v2

- Data IS relational (accounts → apps → jobs)
- Already thinking in SQL (SQLite schema exists)
- Scales to near-zero when idle
- Same SQL works locally (SQLite) and cloud (Postgres)

### S3 for Artifacts

- JSON reports (large, don't need querying)
- Generated Java code ZIPs
- COBOL upload ZIPs
- Transformation logs

---

## Key Principles

1. **One relational database** - Aurora PostgreSQL for all structured data
2. **One object store** - S3 for all artifacts
3. **API is the gatekeeper** - All data flows through FastAPI
4. **Desktop mirrors cloud** - SQLite locally, sync through API
5. **Simplicity wins** - No DynamoDB, no Mongo, no unnecessary complexity
