### Workflow Navigation UX Issue

**Problem Identified:**
- When user runs a workflow, they're stuck on that page
- Can't navigate to view graphs/reports while workflow is running
- If they navigate away, they lose the running workflow
- Results in poor UX - user is "trapped" during 5-10 minute workflows

**Current State:**
- Jobs database already exists (tracks all workflow executions)
- Jobs have: job_id, status, timestamps, account/app info
- Data is saved to disk/S3 when workflows complete
- Infrastructure is there, just need better UI

**Proposed Solutions:**

**Option 1: Background Jobs + Toast Notifications** (SIMPLEST - RECOMMENDED)
- Let workflows run in background (API already does this)
- Show toast: "Workflow started! Check Reports when ready"
- User navigates freely
- Optional: Toast notification when workflow completes
- No complex state management needed
- Implementation: Add react-hot-toast (or similar), remove blocking UI

**Option 2: Jobs Status Panel**
- Add "Jobs" dropdown in header
- Shows: "2 workflows running"
- Click to expand: see running/completed jobs
- User can check status anytime
- More UI work, but better visibility

**Option 3: Simple Status Indicator**
- Small banner at top: "Discovery running... (2 min remaining)"
- Store workflow state in localStorage/context
- Poll API every 10s to check completion
- Let user navigate freely

**Decision:**
- Focus on core use case: Upload → Analyze → View Results
- Don't over-engineer infrastructure (spent 12+ hours on accounts/projects already)
- Implement simplest solution that works
- Can enhance later if needed

**Action Items for Next Session:**
- [ ] Decide on approach (recommend Option 1)
- [ ] Implement background workflow execution
- [ ] Add toast notification system
- [ ] Remove blocking "running" screens
- [ ] Test user flow end-to-end
- [ ] Keep it simple - don't overdo it

**Priority:** Medium (after reports are perfect and deployment is done)
