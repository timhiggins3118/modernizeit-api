## Bug Fix: Generic Paragraph Prefix Detection

### Issue
- CMCMCL00.CBL paragraphs not being classified - 0 PARAGRAPH entries
- Java generation produced stub methods with `// TODO` instead of implementations

### Root Cause
- Original regex `\d{2,4}` only matched 2-4 digit prefixes
- IBMi-Cobol uses 5-digit prefixes: `00000-MAIN-CONTROL-ROUTINE.`
- Other dialects may use varying digit counts

### Fix
- Updated regex from `\d{2,4}` to `\d+` (one or more digits)
- Now matches ANY numeric prefix: `0-`, `00-`, `000-`, `00000-`, `000000-`, etc.
- File: `engines/code_analysis/parsers/cobol_parse_export.py` line 269

### Verified
- IFPR321 (3-digit prefixes): 288 PARAGRAPH classifications ✓
- Generic solution works for any COBOL dialect

## Bug Fix: Graph Generator Hardcoded Filenames

### Issue
- Graphs only generated for IFPR321, failed for other programs
- Graph functions had hardcoded `ifpr321_file_model.json` and `ifpr321_procedure_model.json`
- DOT node IDs contained hyphens (invalid syntax)

### Fix
1. Added `base_name` parameter to all 3 graph functions
2. Functions now use `{base_name}_file_model.json` and `{base_name}_procedure_model.json`
3. Auto-detect base_name from existing files if not provided
4. Sanitize file node IDs: `FILE-NAME` → `FILE_NAME` for DOT compatibility
5. Updated `runner.py` to pass `base_name` to graph functions
