## IBM watsonx Code Assistant Analysis

Reviewed `/Users/timhiggins/Desktop/_IBM/ibm-watsonx-docs.md`

### IBM's Two-Tool Workflow

| Tool | Interface | Purpose |
|------|-----------|---------|
| **Refactoring Assistant** | Web browser | Dependency visualization, paragraph analysis, workbook creation |
| **watsonx Code Assistant for Z** | VS Code extension | Java class/method generation from COBOL |

### Key Insight: "Refactoring" = Preparation, Not Modification

IBM's "refactoring" does NOT modify COBOL. It:
1. **Identifies logical units** - Paragraphs that become Java methods
2. **Creates workbooks** - Groups related code blocks for conversion
3. **Maps names** - COBOL conventions → Java conventions
4. **Prepares for conversion** - Organizes before AI generates Java

### IBM's Conversion Flow

1. Import COBOL into Refactoring Assistant
2. Analyze dependencies (Graph view)
3. Select program → "Identify paragraphs"
4. Create workbook (group related code blocks)
5. Open in VS Code with watsonx extension
6. Generate Java class stubs
7. Review COBOL→Java name mappings
8. **Right-click method → "Generate Method"** (AI fills implementation)
9. Review/rate generated code

### Generated Java Structure

| COBOL Artifact | Java Target |
|----------------|-------------|
| Program | Service class |
| Copybook | DTO/POJO |
| DB2 table | JPA Entity |
| Paragraph | Method |
| COMMAREA | Request/Response DTO |

### What Rules Can Detect (Java-side)

**Field-level:**
- Common prefixes (`tax*`, `ded*`, `ern*`) → candidate class grouping
- Arrays of same size used together → related data structure
- 88-level condition methods → enum candidates
- BigDecimal used in loops → should be `int`

**Method-level:**
- Methods with same prefix (`200_*`) → same functional area
- Methods that always call each other → consolidation candidates
- Deeply nested IFs (5+ levels) → complexity smell
- `// GO TO` comments → unhandled control flow

**Structure-level:**
- Parallel arrays → should be `List<Object>`
- Inner classes with only fields → records or POJOs
- 500+ fields in one class → needs splitting

### What AI Decides

Things rules CAN'T do:
- "These 47 fields are all about **tax calculation**" (semantic grouping)
- "This method should be called `calculateFederalWithholding`" (meaningful naming)
- "These 3 methods form a **transaction boundary**" (business logic)
